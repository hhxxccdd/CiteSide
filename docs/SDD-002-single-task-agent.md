# SDD-002：用选定资料完成一次研究任务

> 2026-10-19。替代必须有选区、每次必查知识库、切页自动停止的旧规则。正文读取见 SDD-001，范围和实施步骤见 SDD-005。全文问答、切页继续、范围开关、仅知识库问答、@ 多资料、会话草稿恢复、流式、主动停止与重试已实现。

## 一次任务是什么

用户提出问题，选择网页和笔记，决定是否搜索个人知识库、是否允许联网，然后开始研究。一次提交就是一次任务，第一版不自动继承所有历史消息。

目前没有多轮对话记忆：上一轮问题和回答不会自动进入下一次模型请求。会话草稿只是恢复界面，知识库检索则需要已确认保存的笔记，两者都不能当作自动记住刚才的对话。2026-10-19 按用户要求恢复到 `9d30813` 的回答流程，原系统提示词末尾只追加“不需要写后续的建议和操作。”已有回答不自动改写。

2026-10-20 补充直接作答的提示：最终答案不输出作答规则、自我评价或内部字段；资料无法回答时说明缺少依据，不先猜测具体事实再否认依据。原问题除了保留在资料 JSON 中，也在最后单独作为自然语言问题提出，让模型明确当前需要回答什么；这不是继承上一轮对话。引用整理也只输出给用户的答案正文。仍沿用原工具和引用流程，不增加文本规则过滤或强制重试。

点击开始时复制问题和资料，形成“任务快照”。之后切页或编辑下一次问题，都不改变本次任务。结果显示实际采用的资料标题，不把正在浏览的新页面误当成来源。

## 后端执行顺序

1. 检查问题、数量、大小和范围。没有网页也能只查知识库；没有指定资料且两个搜索开关都关闭时，提示先选择范围。
2. 分配运行 ID，固定问题、网页正文、指定笔记 ID 和开关。后端按 ID 读取指定笔记，不能把前端传入的笔记正文当成数据库原文；笔记不存在时明确提示。
3. 有网页时固定读取本次提交的快照。现有 read_current_context 调整为处理网页列表，无网页则跳过；不声称模型自行读取了浏览器。
4. 开启“搜索个人知识库”才执行 search_knowledge_base。用问题为主、网页标题等有限背景为辅检索，不把三篇全文拼成查询向量。沿用向量召回和相关性判断，最多留下 3 条。
5. @ 指定的笔记直接加入，不因为相似度不高而静默删除。和自动召回结果按笔记 ID 去重。关闭自动搜索不影响明确指定的笔记。
6. 允许联网时进入有次数上限的工具循环：模型发现缺失信息后搜索，优先阅读相关的官方文档或项目源码，再判断是否足够回答。必要时换搜索词补查一轮。最多搜索 2 次、阅读 3 篇；次数是本次请求内的总次数，失败尝试也计入。关闭联网时不提供工具，执行器也拒绝执行，不能只靠提示词限制。
7. 基于实际资料生成回答、来源和提示。用户添加的浏览器网页不消耗模型联网阅读次数。网页里的指令不能覆盖用户问题、系统规则和工具限制。

复用联网工具已有的参数检查、来源网址限制和失败处理，不把 @ 网页做成模型任意读取 URL 的入口。粘贴 URL 的功能后续再做。

### 工具调用保持简单

允许联网只表示模型可以使用工具。真正执行仍需要模型返回 tool_calls；单纯写出“需要你执行该搜索”不会自动开始搜索。当前通过准确的提示词区分本轮工具执行与回答结束后的额外服务，不再用正则猜测模型意图或强制补调用。

流程保留三个简单规则：

- **模型返回 tool_calls**：校验参数后执行真实工具，再把结果交给模型回答。
- **模型只返回文字**：作为回答，不额外判断“像不像调用计划”，也不强制重新请求工具。
- **引用整理**：沿用原对话和首次回答，最多补充整理一次引用；原有缺失引用提示保留。

单轮问答仅表示不自动继承上一轮历史，不禁止本轮多次调用工具。联网开关、最多 2 次搜索和 3 篇阅读、参数与网址校验、真实工具失败和资料不足提示继续保留。已删除 research-answer-policy.ts 及具名 tool_choice 补请求，工具选择统一使用 auto。提示词无法绝对保证模型每次表达正确，出现异常时检查模型返回与实际工具结果，不增加文本猜测层。

### 允许联网后，何时应该搜索（2026-10-20）

“允许联网”是本轮搜索的许可，是否需要调用仍由模型判断。现有资料足以回答整个问题时可以直接回答；问题有必要事实未被覆盖时，应先补查，不能仅以“当前网页没提到”为由结束回答。例如用户同时询问 KeepAlive 的作用和具体使用项目，官方机制说明只覆盖前半问，模型应搜索后半问的实例。无需再次向用户请求已经给出的联网许可。

主提示词、最后的原问题提示和搜索工具描述保持这一规则一致。“不附后续建议”只约束最终答案，不妨碍本轮执行工具。仍使用 auto，不增加关键词路由、文本判定后的强制重试或每次必搜。执行记录如实显示模型是否请求搜索，不能把开启开关显示成已完成搜索。搜索后没有可核实证据时，仍应说明限制，不能为列出案例而编造网站或项目。

具体项目采用了某项技术的结论，需要正文或源码支持。每次工具返回后明确当前任务：结果标题和模型生成摘要只作线索，需要补充事实时阅读相关原文；一篇文章无关或读取失败，可以换另一篇，或调整搜索词，不直接判定网上没有答案。工具选择继续由模型通过 tool_calls 返回，不把提示词当成绝对保证。

### 补查循环的执行边界（2026-10-20）

- 执行器只提供仍有余额的工具，阅读工具只接受本轮搜索所得、尚未尝试的网页序号。不能自行编造 URL。
- 两次搜索结果按规范化 URL 去重并追加；已有来源编号不变，第二轮不能把第一轮的引用指向另一篇网页。
- 已读正文完整留在本轮消息里，最终来源表为每篇成功读取的网页提供对应片段和阅读状态。兼容旧的 readPage，同时增加 readPages 与逐篇失败信息。
- 相同搜索词、已尝试网页不重复执行。参数错误、未知工具与超限请求通过工具结果反馈；最多进行 7 轮模型决策，防止不断发出无效调用。
- 资料足够时模型直接回答，不要求把次数用满；次数耗尽时撤下工具，基于已有证据收尾，缺少的部分如实说明。
- 每次真实搜索、读取和失败都有独立执行事件，搜索显示本次关键词及结果，阅读显示目标网页。停止后不再发起下一轮。

本轮只修改既有研究执行器、来源构建、接口类型和文档，不新增通用 Agent 框架或长期记忆。

## 失败时怎样处理

- 网页正在读取、未授权或失败：提交前提示重试或移除，不悄悄忽略。
- 指定笔记已删除：保留问题，提示移除失效资料后重试。
- 自动知识库搜索失败：有其他资料可继续，但明确提示；只有知识库范围时说明失败，不能伪装成检索成功。
- 联网失败或资料不足：只用已取得内容回答，不能编造来源或声称已查证。
- 模型报错或服务断开：保留问题、资料与上一份完成结果。

## 切换网页怎样处理

| 操作 | 正在浏览 | 下一次提问草稿 | 任务和答案 |
| --- | --- | --- | --- |
| 从 A 切到 B，或 A 跳转 | 更新为 B | 保留已加入的 A，提示可添加 B | 按 A 快照继续，不清空、不自动停止 |
| 点击引用打开新标签页 | 更新 | 保留 | 回答和引用保留 |
| 关闭资料标签页 | 更新 | 已读快照保留；未读附件提示失效 | 已提交快照继续可用 |
| 重新读取网页 | 更新附件 | 显示新的读取时间 | 不改写旧任务资料 |
| 切到“我的知识” | 不影响 | 保留 | 同一侧栏里的任务继续 |
| 点击“新建研究” | 不影响 | 重置问题和资料，按当前页初始化 | 进行中需先停止；旧完成结果保留到新结果成功或明确清除 |

草稿不因切页偷偷绑定新网页。网页读取错误不遮挡旧回答或保存编辑区。重试使用原问题和原快照，创建新运行 ID，不自动改用正在浏览的页面。

## 流式、停止与恢复

原 JSON 接口继续保留，侧栏已使用 POST 事件流。具体事件、停止与验收规则见 [SDD-007](SDD-007-streaming-research.md)。不能用固定动画冒充真实工具事件。

用 POST 加 fetch 接收事件流。每个事件有 runId、递增序号和类型，覆盖开始、步骤开始/完成/失败、回答片段、完成和失败。停止由关闭连接触发，前端立即更新状态，不依赖已关闭的连接传回停止事件。前端只接受当前运行事件，旧请求片段不能追加到新答案。

用户点击停止才中止请求；后端在连接断开时取消模型调用，不启动后续工具，并释放资源。切页不停止。同一窗口一次只运行一个任务，停止后可以重新提交。

第一版不保证关闭侧栏后持续运行。侧栏真正卸载时中止请求，重开标为“任务已中断”，恢复草稿和最近完成结果，不自动重发。切到“我的知识”只隐藏研究界面，不卸载运行状态。浏览器重启或扩展重载后不承诺恢复。

## 数据放在哪里

按 windowId 在 Chrome 会话存储中保留草稿、保存编辑内容和最近一次完成结果；完成结果包括原问题、资料摘要、答案与引用片段。运行状态和当前浏览页分开，读取中附件恢复后提示重试。

正文只用于会话与本次请求，不自动入 PostgreSQL。数据库继续保存用户确认的笔记与向量。本轮不建任务表、事件表或完整历史；旧稿中的任务事件永久存储计划延后。密钥只在后端。

## 验收

分别完成单网页、仅知识库、网页加指定笔记、两网页对比。关闭范围后确实不调用相应搜索。生成中切页仍基于原资料，重试沿用原快照，停止和断网不会混入迟到事件。来源真实，保存仍需人工确认。
