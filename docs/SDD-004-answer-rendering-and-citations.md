# SDD-004：把回答排版好，并在正文中查看引用

> 2026-10-19。排版与自然文字引用已实现；本次对齐新的多资料与切页规则，多篇网页、指定笔记来源与切页继续已接通。对应 PRD 的 F5，补充 SDD-002、SDD-005。

## 为什么现在的回答很乱

模型返回的文字使用了 Markdown，比如 `##` 表示标题、`**文字**` 表示加粗、竖线表示表格。当时页面通过 Vue 的文字插值直接显示答案，所以这些标记没有变成对应的页面元素。

这通常叫“Markdown 未渲染”或“Markdown 渲染缺失”。表格和代码挤出侧栏，则是“内容溢出”。它们主要是展示问题；把答案排版好，并不能证明答案本身正确。

正文中可以查看来源的文字叫“行内引用”，鼠标放上去显示来源卡片叫“引用预览”。底部列出了资料，不代表回答真的引用了资料。

## 用户会看到什么

1. 标题、加粗、列表、引用段落、代码和表格会正常排版。
2. 代码块和宽表格可以在自己的区域横向滚动，整个侧栏不会被撑宽。
3. 回答需要引用来源时，把相关结论或术语显示为带下划线的自然文字，不给用户显示 S1、N1 或数字角标。
4. 鼠标放上引用文字，或用键盘选中链接，会显示来源类别、标题、网址和已有的原文片段。点击文字或卡片中的链接可以打开原网页。
5. 个人笔记也显示保存的正文片段及原网页链接。搜索结果只有标题和网址时，明确标为“搜索结果，原文未核对”，不会伪造原文。
6. 底部继续保留参考资料列表；只有与正文引用文字关联的真实资料，才标为“已引用”。

## 引用怎样对应

每次提问使用自己的来源表：

| 来源编号 | 内容 |
| --- | --- |
| S1、S2…… | 本次实际提交的网页正文快照 |
| N1、N2…… | 本次指定或实际检索到的笔记，按笔记 ID 去重 |
| W1、W2…… | 本次实际返回的联网搜索结果 |

这些编号仅用于程序内部对应资料。用户添加的浏览器网页用 S 类编号，模型联网取得的网页用 W 类编号，来源要区分“用户提供的网页”和“联网资料”。已阅读的搜索网页沿用搜索结果编号。后端要求 Qwen 直接把引用文字写进句子，例如：`TypeScript 会[依据条件缩小变量类型范围][S1]。` 用户实际看到的是带下划线的“依据条件缩小变量类型范围”，悬停可以查看原网页信息。

后端响应的 `sources` 数组包含内部标识、类别、标题、网址、原文片段和阅读状态。已将旧的 selection 类别改为 page；笔记已增加 noteId，无网页来源时通过受信任的内部锚点打开笔记详情；锚点仅在真实来源表存在该笔记时生成，不开放任意协议。老会话无法安全迁移时按版本清理，不能把选区伪装成完整正文。当前会话使用 completedResearch:v3 键，并兼容 completedPageResearch:v2 单篇结果，旧选区回答不冒充全文结果。前端据此生成文字链接。代码中的标记保持代码原样；未知来源只保留自然文字，不显示无效内部标记，也不生成假链接。旧版单独的内部标记会显示成来源标题，避免向用户暴露实现细节。

前端在显示时根据真实来源补齐 Markdown 引用链接。打开保存编辑区前，将它转换为普通的具名 Markdown 链接，例如 `[依据条件缩小范围](<https://example.com/article>)`。用户编辑、保存和以后查看笔记时，都不需要知道内部编号。代码内容保留原样。

编号校验只能保证“确实有这个来源”，不能自动保证“这个来源支持这句话”。用户仍需要查看片段或原网页核对。旧回答没有来源编号时，不在事后猜测哪句话引用了哪篇文章。

## 排版和安全怎样处理

采用 markdown-it 解析 Markdown，再用 DOMPurify 清理生成的 HTML。模型输出不是可信网页，不能直接交给 `v-html`。默认关闭原始 HTML；兼容模型表格中常见的 `<br>` 换行，只允许这一种简单换行写法。图片和嵌入内容不加载，链接只接受 HTTP/HTTPS。

表格外面加可横向滚动的容器；代码使用等宽字体并独立滚动。提示模型优先简洁段落和列表，侧栏中少用很宽的表格。格式要求只能减少问题，不能代替前端渲染。

如果模型本身写出了不符合 Markdown 语法的表格，解析器也无法保证恢复出正确表格；这时应重新生成或改用列表，不能把自动修复当成事实核对。

引用预览由 Vue 自己生成，内容来自来源表。支持鼠标悬停、键盘聚焦、点击跳转和 Escape 关闭；卡片会留在侧栏可见区域内。

保存笔记时保存含正常网页链接的 Markdown 正文，不依赖某次问答临时的来源表。旧笔记的内部引用定义在进入编辑区时也会转成具名链接。笔记详情继续复用 Markdown 展示。

## 为什么点来源后回答消失，怎样修

旧代码在“当前选区变化”时同时清空了已完成回答。点击来源打开新标签页，会触发清除旧选区，进而误删回答。

新设计分开维护当前浏览页、研究草稿和任务快照。切页只更新当前浏览页，不替换草稿资料，不清空回答和保存编辑区，也不停止正在生成的回答。只有用户主动停止、请求失败或侧栏真正卸载才中断；迟到结果不能覆盖新任务。新提问成功后才替换上一份完成结果。单篇全文流程已按此规则替代旧版“选区变化就中断请求”的实现，多资料来源与最近完成结果恢复见 SDD-005，完整草稿恢复仍待完成。

目标是把草稿与最近一次完成问答按浏览器窗口暂存在 Chrome 会话存储。侧栏重新打开时可以恢复；浏览器重启或扩展重新加载后不保留。这不是完整聊天历史，也不会写入知识库。结果区域显示原网页标题和原问题，避免把旧回答误认为基于新网页生成。

## 文件放在哪里

    apps/api/src/research/
      research-sources.ts                 定义来源数据，给真实资料编号
      research.service.ts                 给选定网页和笔记附上编号，返回来源表
      research-tool-runner.service.ts     给联网结果与阅读结果附上编号

    apps/extension/src/features/research-run/
      answerMarkdown.ts                   Markdown 解析、清理和引用识别
      AnswerContent.vue                  排版后的正文与引用预览
      ResearchRun.vue                    连接回答、来源表和保存入口
      researchApi.ts                     补充 sources 的响应类型
      researchSession.ts                 按浏览器窗口暂存最近一次完成的问答

知识库详情复用 AnswerContent，保存组件保留引用对应的网址。第一版不加入通用编辑器，也不增加新的 Agent 工具。

## 做完后怎样检查

- 标题、列表、加粗、行内代码、代码块和表格都能正常显示。
- 在 320、380、500 像素宽度下，页面没有横向溢出；代码和表格内部可以滚动。
- 引用文字可以悬停预览、键盘访问和点击跳转；展示区和保存编辑区不出现内部编号。
- 代码里的编号不被转换；脚本、事件属性和危险网址不能执行。
- 用户提供的网页、指定或召回的笔记、只搜索过的网页、联网读过正文的网页能明确区分。
- 保存后的笔记仍有可用来源链接；正文没引用的资料保持“参考资料”状态。
- 打开引用链接、切换标签页、重新打开侧栏后，上一份已完成回答仍存在；新提问使用用户选定的资料，不要求选区。
- 新请求中断或迟到时，不覆盖上一份完成结果。

此前选区版本已通过两端构建、隔离数据下的 Markdown 与引用交互检查，以及危险内容过滤、代码中编号保留、三个侧栏宽度不溢出、保存后链接仍有效的检查。真实本地 API 的一次 Qwen 提问也返回了 S1 和 N1 编号，知识库检索成功。该真实请求没有保存或修改笔记；联网编号的传递使用受控工具结果验证。这些是旧流程的验证记录，不代表新的正文、多资料和切页继续规则已验收。

## 实现依据

- [markdown-it 安全说明](https://github.com/markdown-it/markdown-it/blob/master/docs/safety.md)：关闭原始 HTML 是推荐的安全使用方式之一。
- [DOMPurify 官方说明](https://github.com/cure53/DOMPurify)：清理 HTML，并限制允许的标签和属性。
