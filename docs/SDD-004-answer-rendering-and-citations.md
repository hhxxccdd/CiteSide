# SDD-004：把回答排版好，并在正文中查看引用

> 2026-10-19。排版与自然文字引用已实现；本次对齐新的多资料与切页规则，多篇网页、指定笔记来源与切页继续已接通。对应 PRD 的 F5，补充 SDD-002、SDD-005。

## 为什么现在的回答很乱

模型返回的文字使用了 Markdown，比如 `##` 表示标题、`**文字**` 表示加粗、竖线表示表格。当时页面通过 Vue 的文字插值直接显示答案，所以这些标记没有变成对应的页面元素。

这通常叫“Markdown 未渲染”或“Markdown 渲染缺失”。表格和代码挤出侧栏，则是“内容溢出”。它们主要是展示问题；把答案排版好，并不能证明答案本身正确。

正文中可以查看来源的文字叫“行内引用”，鼠标放上去显示来源卡片叫“引用预览”。底部列出了资料，不代表回答真的引用了资料。

## 用户会看到什么

1. 标题、加粗、列表、引用段落、代码和表格会正常排版。
2. 代码块和宽表格可以在自己的区域横向滚动，整个侧栏不会被撑宽。
3. 回答需要引用来源时，把相关结论或术语显示为带下划线的自然文字，不给用户显示 S1、N1 或数字角标。
4. 鼠标放上引用文字，或用键盘选中链接，会显示来源类别、标题、网址和已有的原文片段。点击文字或卡片中的链接可以打开原网页。
5. 个人笔记也显示保存的正文片段及原网页链接。搜索结果只有标题和网址时，明确标为“搜索结果，原文未核对”，不会伪造原文。
6. 底部继续保留参考资料列表；只有与正文引用文字关联的真实资料，才标为“已引用”。

## 引用怎样对应

每次提问使用自己的来源表：

| 来源编号 | 内容 |
| --- | --- |
| S1、S2…… | 本次实际提交的网页正文快照 |
| N1、N2…… | 本次指定或实际检索到的笔记，按笔记 ID 去重 |
| W1、W2…… | 本次实际返回的联网搜索结果 |

这些编号仅用于程序内部对应资料。用户添加的浏览器网页用 S 类编号，模型联网取得的网页用 W 类编号，来源要区分“用户提供的网页”和“联网资料”。已阅读的搜索网页沿用搜索结果编号。后端要求 Qwen 直接把引用文字写进句子，例如：`TypeScript 会[依据条件缩小变量类型范围][S1]。` 用户实际看到的是带下划线的“依据条件缩小变量类型范围”，悬停可以查看原网页信息。

后端响应的 `sources` 数组包含内部标识、类别、标题、网址、原文片段和阅读状态。已将旧的 selection 类别改为 page；笔记已增加 noteId，无网页来源时通过受信任的内部锚点打开笔记详情；锚点仅在真实来源表存在该笔记时生成，不开放任意协议。老会话无法安全迁移时按版本清理，不能把选区伪装成完整正文。当前会话使用 researchWorkspace:v1，兼容 completedResearch:v3 与 completedPageResearch:v2 单篇结果，旧选区回答不冒充全文结果。前端据此生成文字链接。代码中的标记保持代码原样；未知来源只保留自然文字，不显示无效内部标记，也不生成假链接。旧版单独的内部标记会显示成来源标题，避免向用户暴露实现细节。

前端在显示时根据真实来源补齐 Markdown 引用链接。打开保存编辑区前，将它转换为普通的具名 Markdown 链接，例如 `[依据条件缩小范围](<https://example.com/article>)`。用户编辑、保存和以后查看笔记时，都不需要知道内部编号。代码内容保留原样。

编号校验只能保证“确实有这个来源”，不能自动保证“这个来源支持这句话”。用户仍需要查看片段或原网页核对。旧回答没有来源编号时，不在事后猜测哪句话引用了哪篇文章。

## 为什么提示有划线，回答却没有

此前的悬停提示是固定文案，即使模型没有写出可识别引用也会显示，因此可能与实际回答不一致。只有回答中的有效引用关联到真实来源，前端才会生成划线和悬停卡片；把资料列在底部不会自动让每句话获得引用。

修复分两层：

1. **界面按真实引用显示提示**：有引用才提示悬停；有资料但没有引用时，显示“未提供可核对的正文引用”，并说明下方只是本次取得的资料。旧答案也会按此规则显示，不自动改写或随意添加链接。
2. **后端检查新回答**：ResearchCitationsService 通过 markdown-it 判断是否至少存在一个有效来源引用，代码块、行内代码和未知编号不计入。有资料却没有有效引用时，把实际输入与工具结果交给 Qwen，最多整理一次。要求删除资料不支持的具体统计、比例、薪资和招聘结论，不把来源硬接到旧句子上。没有资料依据时可以直接说明无法确认，不强行引用。

已有有效引用或没有来源时不增加调用。一次整理仍缺引用时停止重试，由界面明确提示；整理请求失败则保留首次回答并提示。这个步骤可能增加一次模型调用及等待时间。它检查引用格式和对应关系，不是逐句事实核验；有一个引用也不代表整篇回答已获验证。

引用整理没有工具可用，系统提示明确工具阶段已经结束，只能整理已有资料，不能要求用户或程序再搜索。已移除 research-answer-policy.ts 以及正则判断和兜底替换；保留一次整理上限、整理请求失败时返回原回答、无有效引用时的界面提示。该提示词约束不能当成模型输出的绝对保证。

## 排版和安全怎样处理

采用 markdown-it 解析 Markdown，再用 DOMPurify 清理生成的 HTML。模型输出不是可信网页，不能直接交给 `v-html`。默认关闭原始 HTML；兼容模型表格中常见的 `<br>` 换行，只允许这一种简单换行写法。图片和嵌入内容不加载，链接只接受 HTTP/HTTPS。

表格外面加可横向滚动的容器；代码使用等宽字体并独立滚动。提示模型优先简洁段落和列表，侧栏中少用很宽的表格。格式要求只能减少问题，不能代替前端渲染。

如果模型本身写出了不符合 Markdown 语法的表格，解析器也无法保证恢复出正确表格；这时应重新生成或改用列表，不能把自动修复当成事实核对。

引用预览由 Vue 自己生成，内容来自来源表。支持鼠标悬停、键盘聚焦、点击跳转和 Escape 关闭；卡片会留在侧栏可见区域内。

来源正文不再直接显示 Markdown 字符串。悬停卡片和展开资料统一使用 SourceExcerpt：标题、段落、加粗、列表、代码和表格排版后展示，链接只保留文字，避免标题锚点和网址占满预览；跳转仍通过独立的“打开原网页”。解析复用 markdown-it，输出经 DOMPurify 清理，不加载图片或执行网页 HTML。仅调整显示，保留原始提取内容供模型读取。

保存笔记时保存含正常网页链接的 Markdown 正文，不依赖某次问答临时的来源表。旧笔记的内部引用定义在进入编辑区时也会转成具名链接。笔记详情继续复用 Markdown 展示。

## 为什么点来源后回答消失，怎样修

旧代码在“当前选区变化”时同时清空了已完成回答。点击来源打开新标签页，会触发清除旧选区，进而误删回答。

新设计分开维护当前浏览页、研究草稿和任务快照。切页只更新当前浏览页，不替换固定的 @ 资料，不清空回答和保存编辑区，也不停止正在生成的回答。请求失败或侧栏真正卸载时停止前端等待；迟到结果不能覆盖新任务。主动停止与后端取消将在流式阶段实现。新提问成功后才替换上一份完成结果。多资料来源、草稿与笔记编辑恢复已接通，详见 SDD-005。

草稿与最近一次完成问答已按浏览器窗口暂存在 Chrome 会话存储，侧栏重新打开时可恢复；浏览器重启或扩展重新加载后不承诺保留。这不是完整聊天历史，也不会自动写入知识库。笔记编辑绑定结果 runId，结果区域显示原网页标题和原问题，避免把旧回答误认为基于新网页生成。

## 做完后怎样检查

- 标题、列表、加粗、行内代码、代码块和表格都能正常显示。
- 在 320、380、500 像素宽度下，页面没有横向溢出；代码和表格内部可以滚动。
- 引用文字可以悬停预览、键盘访问和点击跳转；展示区和保存编辑区不出现内部编号。
- 代码里的编号不被转换；脚本、事件属性和危险网址不能执行。
- 用户提供的网页、指定或召回的笔记、只搜索过的网页、联网读过正文的网页能明确区分。
- 保存后的笔记仍有可用来源链接；正文没引用的资料保持“参考资料”状态。
- 没有引用时不出现悬停提示；无效编号和代码示例不会阻止一次整理，整理失败也不伪造链接。
- 打开引用链接、切换标签页、重新打开侧栏后，上一份已完成回答仍存在；新提问使用用户选定的资料，不要求选区。
- 新请求中断或迟到时，不覆盖上一份完成结果。

此前选区版本已通过两端构建、隔离数据下的 Markdown 与引用交互检查，以及危险内容过滤、代码中编号保留、三个侧栏宽度不溢出、保存后链接仍有效的检查。真实本地 API 的一次 Qwen 提问也返回了 S1 和 N1 编号，知识库检索成功。该真实请求没有保存或修改笔记；联网编号的传递使用受控工具结果验证。这些是旧流程的验证记录，不代表新的正文、多资料和切页继续规则已验收。

## 联网搜索成功，为什么仍可能答不出来

搜索到网页，不等于读到了网页。搜索工具返回的模型总结也不是网页原文，不能直接当作已核实的统计数据。按用户要求恢复 `9d30813` 的回答流程后，搜索工具的总结与候选标题、网址一起传给回答模型；模型按需选择其中一篇读取正文。来源表仍区分搜索结果与已读正文。

例如问“TS 知识点在前端实习中的分布比例”，技术教程只能说明 TS 有哪些知识点，几条招聘信息也不能证明整个市场的比例。没有可靠统计时应说明资料不足，不能编一个百分比。

2026-10-19 实测：搜索返回了一条 BOSS 直聘岗位页，读取时网站返回 HTTP 302，跳到 `/web/passport/zp/security.html` 安全验证页。旧代码禁止所有跳转，只显示 `fetch failed`，前端又把具体错误缩成“网页原文读取失败”，因此用户无法判断哪一步出了问题。

这次处理：

- 同一主机的普通地址跳转最多跟随三次，总读取时间仍为 10 秒；不跟随站外跳转和 HTTPS 降级。
- 跳到登录或安全验证入口时停止，不把验证页面当作文章。网站拒绝访问、限流、超时等分别说明原因。
- 回传读取失败的文章标题、地址和原因；侧栏显示标题与原因，后端日志保留地址，方便排查。
- 读取失败后仍基于已有资料回答，不声称核对过原文，也不绕过网站验证。用户可以自己打开网页，正常加载正文后用 `@` 添加。
- 保持一次搜索、最多读取一篇网页的现有范围。这不是跨多个岗位做统计的工具。

引用整理恢复为原先的方式：沿用本次对话、首次回答和来源表，缺失引用时最多请求模型整理一次。回答提示词相对 `9d30813` 只追加“不需要写后续的建议和操作。”，不再叠加独立编辑任务与额外结尾约束。

仍沿用已有文件：`read-web-page.tool.ts` 负责下载与跳转；`research-tool-runner.service.ts` 负责执行工具和传递失败原因；`research-citations.service.ts` 负责引用整理；`researchApi.ts`、`ResearchRun.vue` 接收和显示结果。没有增加通用调度层或新的工具。

验证记录：TypeScript 官方文档实际读取成功；上述 BOSS 直聘地址实际返回安全验证提示。受控检查覆盖普通跳转、跳转次数、站外地址、HTTP 降级、403/429、非 HTML、下载大小和失败信息传递。侧栏在 320 像素宽度下可显示失败文章与原因，原有问答、引用、资料选择和笔记编辑流程检查通过。这不意味着任意网站都能由服务端读取。

## 实现依据

- [markdown-it 安全说明](https://github.com/markdown-it/markdown-it/blob/master/docs/safety.md)：关闭原始 HTML 是推荐的安全使用方式之一。
- [DOMPurify 官方说明](https://github.com/cure53/DOMPurify)：清理 HTML，并限制允许的标签和属性。
