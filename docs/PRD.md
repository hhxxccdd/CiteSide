# ResearchFlow — 基于浏览器上下文的 AI Research Agent

> 版本：v1.0｜日期：2026-10-07｜目标：在 2026-10-28 前完成可演示的第一版，随后转入 `md-kb` 修复与求职准备。

## 1. 产品概述

ResearchFlow 是一款面向技术资料阅读的 Chrome 扩展。用户在技术文章或官方文档中选中内容，打开侧栏提出问题；Agent 结合当前页面和用户保存的资料，调用工具查找证据，逐步生成带来源的回答。用户可以确认并保存知识卡片，供后续研究时检索。

**核心价值：**将“读网页 → 查已有资料 → 理解差异 → 留下可追溯笔记”放在当前浏览器页面旁完成。

**目标用户：**阅读前端、全栈和 AI 工程技术文档的开发者。第一版为单用户个人工具。

## 2. 第一版边界

| 范围 | 第一版要求 |
| --- | --- |
| 目标网页 | 可访问的 HTML 技术文章与官方文档；优先支持用户选区，正文提取作为补充 |
| 输入 | 当前标签页标题、URL、选区或正文片段，以及用户提出的问题 |
| 输出 | 流式回答、可点击的来源、工具执行记录、待确认的知识卡片 |
| 资料库 | 独立于 `md-kb`，保存用户明确选择收藏的网页资料和卡片 |
| AI 服务 | 使用用户已有的大模型 API Key；Key 仅存放在后端环境变量中 |
| 运行方式 | 本地启动 NestJS 与 PostgreSQL；Chrome 以“加载已解压的扩展程序”方式安装；不依赖上架商店 |

**第一版不做：**任意网站自动巡航、搜索引擎搜索、登录页抓取、PDF/视频解析、多人账户、跨设备同步、学习任务编排、多 Agent 协作。页面抽取失败时，允许用户改用手动选区继续。

## 3. 核心使用流程

1. 用户打开技术文章，选中一段文字并点击扩展图标，侧栏显示页面标题、URL 和选区预览。
2. 用户提出问题，例如：“这段 `watchEffect` 的行为与我之前保存的 `computed` 资料有什么区别？”
3. 后端创建一次研究任务。Agent 根据问题决定读取当前上下文、检索资料库、查看命中的资料片段，侧栏实时展示每一步及状态。
4. Agent 输出结论，并为来自网页或资料库的关键说法标明来源。证据不足时明确说出缺口，不编造引用。
5. 用户点击“生成卡片”查看草稿，可以编辑标题、摘要和标签；只有点击“确认保存”后才写入资料库。
6. 下次研究时，已保存的网页资料和卡片可以作为检索依据。

## 4. 功能需求

### P0：投递前必须完成

| 编号 | 功能 | 完成标准 |
| --- | --- | --- |
| F1 | Chrome 侧栏 | 扩展图标打开 Vue 3 侧栏；能展示当前页面标题、URL、选区；当前页不支持读取时有明确提示 |
| F2 | 网页内容读取 | 在用户主动发起操作后读取选区或正文；限制传输长度；显示即将发送给后端的内容预览 |
| F3 | 资料收藏 | 用户可手动收藏当前网页的标题、URL、摘录和正文片段；支持列表查看、删除 |
| F4 | 上下文问答 | 可询问当前网页；回答以增量形式出现在侧栏；支持停止生成与错误重试 |
| F5 | 有边界的 Agent 循环 | Agent 可在 `read_current_context`、`search_library`、`read_saved_source` 中选择工具，最多执行 4 次工具调用；记录调用、结果摘要及结束原因 |
| F6 | 来源引用 | 回答引用当前网页或已保存资料，来源可点击并能看到对应摘录；查不到依据时显示“资料不足” |
| F7 | 知识卡片确认 | Agent 可提出卡片草稿；用户确认前不能写入资料库；卡片保存后可查询、编辑和删除 |
| F8 | 演示与交付 | 提供可重复的演示数据、安装说明、环境变量样例、启动命令和 2 分钟演示流程 |

### P1：P0 稳定后再做

- **基础向量检索：**若现有服务支持 Embedding API，用 PostgreSQL + pgvector 保存资料片段向量，提供与关键词检索的对比案例。少量资料先用精确相似度搜索，不急于建立近似索引。
- **执行历史恢复：**侧栏关闭后重新打开，可查看已完成的研究任务和工具记录。
- **导出卡片：**导出 Markdown，便于用户迁移资料。

### P2：投递后再考虑

- 多标签页对照研究、网页自动导航、批量资料导入、`md-kb` 同步、学习任务规划。

## 5. 页面与交互

侧栏只保留四个主要视图：

1. **研究：**当前网页信息、选区预览、问题输入框、流式回答、来源列表。
2. **执行过程：**按时间顺序显示“读取当前页／检索资料／阅读资料／生成结论”，每一步可展开查看输入摘要、结果摘要和状态；不展示模型内部推理文本。
3. **资料库：**已收藏网页与知识卡片的列表、搜索和删除。
4. **卡片确认：**草稿预览、标题和内容编辑、确认保存或放弃。

用户切换标签页后，侧栏提示重新读取当前页；不能把上一标签页的内容当作当前上下文。停止任务后，界面明确显示“已停止”，不继续呈现迟到的回答片段。

## 6. Agent 与技术设计

**技术栈：**Chrome Extension Manifest V3、Vue 3、TypeScript、NestJS、PostgreSQL；P1 使用 pgvector。

**职责划分：**

- **扩展内容脚本：**在用户授权后读取选区和可见正文，发送结构化页面快照。
- **Vue 侧栏：**展示上下文、对话、来源与执行记录；从 NestJS 接收流式事件。
- **NestJS：**保存资料、运行 Agent 循环、调用模型、校验工具参数、生成任务事件；所有模型密钥留在后端。
- **PostgreSQL：**保存资料、摘录、卡片、任务及执行事件；P1 再增加向量字段。

**Agent 状态流：**`创建任务 → 选择工具 → 执行并记录结果 → 判断是否需要继续 → 生成带来源回答 → 等待用户确认卡片`。设置工具次数上限、单次超时和取消信号。模型只能调用预先定义的工具，不能直接执行任意代码、访问任意网页或自行保存卡片。

**来源规则：**当前页快照和已存资料都分配来源 ID。模型返回来源 ID，后端核对其是否属于本次可用证据，再在界面生成可点击引用。工具执行记录展示实际调用和结果，不把预设文案冒充 Agent 决策。

**权限与隐私：**第一版优先使用 `activeTab`，仅在用户点击扩展后获取当前标签页的临时访问权限；不申请全站常驻读取。页面内容在发送前展示预览；仅用户明确收藏的内容持久化。公开演示使用本地服务与演示网页，不把个人资料和 API Key 放进仓库。

## 7. 数据对象

| 对象 | 主要字段 |
| --- | --- |
| Source | ID、标题、URL、摘录、正文片段、收藏时间 |
| Card | ID、标题、内容、标签、引用的 Source ID、创建与修改时间 |
| ResearchRun | ID、问题、页面快照 ID、状态、开始与结束时间 |
| RunEvent | ID、ResearchRun ID、事件类型、工具名、输入与结果摘要、时间 |

P1 的资料切片及向量可附属于 Source。第一版“Memory”指可检索的已存资料和卡片，不宣称具备自主长期记忆。

## 8. 验收场景

1. 在三篇事先选定的公开技术文档中，打开侧栏并读取标题、URL 和用户选区；无法读取正文时，选区流程仍可完成。
2. 收藏两篇相关资料，询问当前选区与其中一篇资料的联系；执行记录中能看到真实的检索工具调用，回答可以打开对应来源与摘录。
3. 在网络中断、模型报错、页面不支持读取时，侧栏给出可理解的错误及重试方式；停止生成后不再追加内容。
4. 生成卡片后点击“放弃”，资料库中不存在该卡片；点击“确认保存”后，重新打开侧栏仍能找到它。
5. 全新环境按 README 能启动后端和数据库、加载扩展，完成上述演示；仓库不包含真实 API Key。

验收使用固定演示网页和明确问题，不以“适配所有网页”作为目标。简历只写实际完成并能现场演示的 P0/P1 能力。

## 10. 简历表达原则

项目名称可写：**ResearchFlow｜基于浏览器上下文的 AI Research Agent**。

项目描述只陈述实际可演示的能力：Chrome 扩展如何取得用户授权与网页上下文、Vue 侧栏如何展示流式执行、NestJS 如何约束工具调用、引用怎样对应真实资料、卡片保存怎样经过人工确认。若 P1 未完成，不写“向量检索”；若仅保存历史记录，不写“长期记忆”。
