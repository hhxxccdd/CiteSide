# ResearchFlow｜技术网页阅读与个人知识助手

> 版本：v1.2｜2026-10-15。先完成一条可演示的使用流程，再逐步补齐体验。本文件描述目标功能，不代表所有功能已经写好。

## 这个项目解决什么问题

读技术网页时，用户常常看不懂某一段，也不记得自己以前是否学过相关内容。ResearchFlow 在 Chrome 侧栏中结合**当前选区、个人笔记和必要时的联网资料**回答问题。用户可以核对来源，并把有价值的回答改写成自己的笔记。

第一版只做本地单人使用，围绕一次提问完成一个小闭环，不做多 Agent、复杂记忆或账号同步。

## 一次完整使用

1. 打开普通技术网页，在网页中选中文字；侧栏先预览，用户点击“使用这段”后才把它作为本次提问的内容。
2. 用户输入问题并开始。后端读取已确认选区，每次搜索个人知识库；如果没有相关笔记，返回空结果。
3. 当问题需要最新信息，或现有资料不足时，Qwen 可以决定调用 `web_search`；找到值得核对的页面后，可以调用 `read_web_page`。后端执行工具，并把结果交回 Qwen。
4. 侧栏显示真实的执行进度和逐步生成的回答。回答旁按“当前选区、个人笔记、联网资料”展示实际取得的来源。
5. 用户可以悬停正文中的引用文字查看来源信息，再点击打开原网页。点击来源或切换网页后，已完成回答仍然保留，并显示它原本对应的网页和问题。一般网页不保证能精确跳到原句，因此要保留可查看的原文片段。
6. 回答完成后，用户可点击“保存到知识库”，在编辑区修改预填的标题和正文，再确认保存。未经用户确认，不自动增加笔记。
7. 下次提问时，新保存的笔记可以通过向量检索被找回。

## 第一版的功能

| 编号 | 功能 | 做到什么算完成 |
| --- | --- | --- |
| F1 | 当前网页 | 侧栏显示当前标签页标题、网址；不能读取时说明原因 |
| F2 | 选区预览与确认 | 选中文字后预览；用户决定使用或忽略；换页后不沿用旧选区 |
| F3 | 一次提问 | 问题与已确认选区一起提交；每次提问有独立状态 |
| F4 | 工具与检索 | 每次读取选区、搜索知识库；Qwen 按需要决定是否联网、是否阅读搜索到的页面；只记录实际执行的工具 |
| F5 | 进度与来源 | 显示真实进度、流式回答和可点击的来源；区分取得的资料与回答实际引用的资料 |
| F6 | 停止与重试 | 可停止当前任务；失败有明确提示；重试创建新任务，不混合两次回答 |
| F7 | 整理并保存 | 回答完成后可编辑标题、正文并确认保存；失败时保留编辑内容 |
| F8 | 个人知识库 | 保存的笔记有原问题和原网页来源；可以查看、修改、删除，并在后续提问中被检索 |
| F9 | 演示交付 | 按 README 能启动并演示选区提问、来源核对、保存笔记和再次找回 |

## 来源怎样展示

侧栏只展示后端**实际取得**的来源，不能让模型编造网址。当前选区必须来自用户本次确认的页面；笔记链接使用数据库保存的来源；联网链接使用搜索或网页阅读工具返回的网址。

“检索到一条笔记”不等于“回答引用了它”。界面先把它列在“参考资料”中；只有回答明确引用并能对应到真实来源 ID 时，才标作“已引用”。点击来源至少能看到保存的原文片段，并能打开原网页或笔记详情。

## 技术与数据边界

- 扩展：Vue 3、TypeScript、Chrome Manifest V3；只把用户确认的选区用于提问。
- 后端：NestJS 负责执行任务、工具与 Qwen 调用；密钥只放在后端环境变量。
- 数据库：本机 PostgreSQL + pgvector 保存用户确认的笔记和向量；普通提问不会自动保存成笔记。
- 工具：`read_current_context` 和 `search_knowledge_base` 每次执行；`web_search` 与 `read_web_page` 由模型按需要调用，后端验证参数并限制次数。
- 第一版不做 PDF、视频、知识图谱、跨网站自动操作、多人协作或云同步。

## 开发与验收顺序

先完成选区和知识库问答，再接入按需联网与网页阅读，随后完成来源卡片、保存前编辑、流式进度和停止重试。每一步都用固定的技术文章验证。最后能演示：**选区提问 → 核对来源 → 编辑并保存 → 换一种问法找回笔记**。
