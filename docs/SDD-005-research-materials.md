# SDD-005：选择资料范围，用 @ 添加网页和笔记

> 2026-10-19。全文问答、范围滑动开关、@ 当前窗口网页和指定笔记已实现。多资料引用与最近完成结果恢复已接通；完整草稿恢复、流式进度和主动停止仍待实现。SDD-001 管网页读取，002 管任务，003 管笔记，004 管回答与引用。

## 借鉴什么

借鉴 Recall 的明确资料范围和 @ 指定资料，让用户看见、添加、移除本次参考内容。不照搬文件夹、标签、知识图谱或三个聊天入口。侧栏是入口，网页和笔记是资料，知识库搜索与联网是两个开关。

闭环：**打开文章 → 加入资料 → 提问和核对引用 → 编辑保存笔记 → 以后检索找回。**

## 界面怎样组织

保留“阅读提问／我的知识”。阅读提问中依次展示：

1. **正在浏览**：当前标签页标题、网址和权限状态，由“使用当前网页”控制是否参加下次提问。
2. **本次参考**：已加入网页和指定笔记的标题卡片，显示就绪状态，可移除；不展示网页正文预览。
3. **问题输入**：输入 @ 或点击“添加资料”打开同一个选择器。
4. **输入框下方**：添加资料按钮和滑动开关。“使用当前网页”“搜索个人知识库”默认开，“允许联网”默认关。
5. **任务和答案**：实际采用的资料、真实进度、答案、引用和保存入口。

当前网页随浏览器切页更新，开关开启时参加下一次提问；缺少权限时显示授权按钮。@ 加入的网页是固定快照，切页不会替换它。已提交任务也固定自己的资料，不跟随新页面变化。当前页不可读时，可关闭“使用当前网页”，只问笔记或其他已选网页。

## @ 选择器

分“已打开网页”和“个人笔记”两组，支持标题搜索。第一版只列当前浏览器窗口的 HTTP/HTTPS 标签页，不读取未选中网页的正文。网页本地筛选；笔记复用列表筛选 API，不为选择资料调用向量模型。

选择后生成卡片，输入框保留问题，附件数据单独记录 tabId 或 noteId，不靠解析 @标题 获取资料。支持上下键选择、Enter 确认、Escape 关闭、鼠标和独立添加按钮。没有结果时明确提示。

网页选中后检查权限、读取正文，显示需要授权/正在读取/已就绪/失败，不要求用户展开或确认正文。授权从明确点击发起，不在搜索列表时自动申请。首次列出其他标签页可能需要授权查看标签页信息；这与读取某个站点正文的权限分开。笔记列表显示标题，提交时后端按 ID 读取最新正文。

最多 3 篇网页、3 条指定笔记。笔记按 ID 去重；网页按去掉片段的完整 URL 去重，保留 query 参数以区分不同内容。自动召回最多 3 条笔记，和指定笔记按 ID 去重。

## 范围的准确含义

| 用户选择 | 后端行为 |
| --- | --- |
| 只有网页，两个开关关闭 | 只使用提交的正文 |
| 没有网页，知识库开启 | 检索个人笔记，不要求当前页可读 |
| 指定笔记，知识库关闭 | 读取指定笔记，不搜索整个库 |
| 指定笔记，知识库开启 | 指定笔记加自动召回结果，去重 |
| 允许联网 | 模型可以按需搜索，不等于已经执行 |
| 没有附件、两个开关都关 | 提示先选择资料范围 |

开关表示“额外去哪里查”，不移除用户明确添加的资料。只问一条指定笔记时，保留笔记卡片，关闭两个开关即可，不增加另一套模式选择。

## 当前 API 契约

POST /api/research/run 已接通以下多资料结构，可直接在 Apifox 中请求。网页的本地附件 ID 和 tabId 不发给后端：

```json
{
  "question": "对比文章中的类型收窄和我的笔记",
  "materials": {
    "pages": [
      {
        "title": "TypeScript 文档",
        "url": "https://example.com/typescript",
        "text": "实际取得的正文……",
        "capturedAt": "2026-10-19T08:00:00.000Z",
        "completeness": "full"
      }
    ],
    "noteIds": ["12"]
  },
  "options": {
    "searchKnowledgeBase": true,
    "allowWebSearch": false
  }
}
```

研究请求的 completeness 只允许 full，不接受部分正文问答。full 表示已加载正文完整提取，不保证原站隐藏或未加载内容已取得。已取消三万字符拦截，采用 SDD-006 修订稿的完整正文直传；不再设计网页分段检索或分层总结。后端校验问题、数量、大小、网址和 ID，不把前端内容当成已核实事实。

最多 3 篇网页（包含当前网页）、3 条指定笔记；所有网页正文合计不超过 8 MiB UTF-8。ID 为正整数十进制字符串，限制在 PostgreSQL bigint 范围内。指定笔记被删除返回 400 并提示移除，数据库暂时不可用返回 503，不悄悄忽略指定资料。

响应保留 answer、sources、runId、options 等字段，增加 specifiedNotes；retrievedNotes 只表示自动检索结果，两者在模型输入和来源表中按 ID 合并去重。网页来源内部标识支持 S1～S3，但界面只显示自然引用文字。无来源网址的笔记仍可在插件内查看，不生成假网页链接。

tabId 留在扩展，不作为后端取网页的凭证。附件本地 ID、任务 runId、回答来源 ID 分开。用户添加的网页不会让模型获得任意 URL 的读取权限。

## 状态和恢复

分别保存三份数据：

- **当前浏览页**：跟随浏览器变化，维护可读性与权限。
- **研究草稿**：问题、网页快照、指定笔记、两个开关、保存编辑内容。
- **研究任务**：提交时固定的资料、状态、回答和来源。

由研究工作区统一持有草稿和任务状态。卡片、选择器、答案组件接收数据并发出操作，不各自存整份状态。先用 Vue composable 和会话存储，不提前引入全局框架。

目前按 windowId 保存最近一次完成结果、该次正文快照、指定笔记和范围。重开侧栏能恢复结果及已完成的指定资料；当前网页仍重新读取。未提交草稿、未完成任务和保存编辑区的跨卸载恢复尚未实现，同一侧栏内切页不会清空它们。浏览器重启或扩展重载不承诺恢复，不做完整历史列表。

## 多来源笔记怎样保存

保存仍需编辑和确认。引用转换成普通具名 Markdown 链接，保留在笔记正文中，不强行假定只参考当前网页。

沿用 sourceTitle/sourceUrl 作为可选主要来源：当前取任务中第一篇网页，否则取实际读取的联网原文；仅笔记问答可留空。不能拿此刻正在浏览的新网页当成原任务来源。其他来源通过正文链接保留；无网址笔记的内部引用在编辑时转换成具名文字。本轮不新增来源关系表，手动选择主要来源暂缓。

## 旧单篇接口兼容

此前 Apifox 中的单篇／无网页请求仍然可用：

```json
{
  "question": "我保存过哪些泛型笔记？",
  "context": null,
  "options": {
    "searchKnowledgeBase": true,
    "allowWebSearch": false
  }
}
```

使用网页时 context 是 SDD-001 的完整正文对象；关闭网页时发 null。新请求统一使用 materials，不能同时提供 context。options 省略时默认查知识库、关闭联网；显式提供时两个字段必须都是布尔值。没有任何资料且两个开关都关闭会被拒绝。

前端使用 completedResearch:v3 会话键；支持读取旧 completedPageResearch:v2 单篇结果并转换，不将更早的选区数据冒充全文。旧结果未记录范围时保留答案，不倒推工具范围。该能力不是完整草稿或聊天历史系统。
