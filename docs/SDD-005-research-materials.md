# SDD-005：选择资料范围，用 @ 添加网页和笔记

> 2026-10-19 新设计稿，也是这轮开发入口。单篇正文问答、取消选区与取消正文预览已完成，范围开关和仅知识库问答已接通，@ 等仍待实现。SDD-001 管网页读取，002 管任务，003 管笔记，004 管回答与引用。

## 借鉴什么

借鉴 Recall 的明确资料范围和 @ 指定资料，让用户看见、添加、移除本次参考内容。不照搬文件夹、标签、知识图谱或三个聊天入口。侧栏是入口，网页和笔记是资料，知识库搜索与联网是两个开关。

闭环：**打开文章 → 加入资料 → 提问和核对引用 → 编辑保存笔记 → 以后检索找回。**

## 界面怎样组织

保留“阅读提问／我的知识”。阅读提问中依次展示：

1. **正在浏览**：当前标签页标题、网址、权限状态和“添加到本次资料”。
2. **本次参考**：已加入网页和指定笔记的标题卡片，显示就绪状态，可移除；不展示网页正文预览。
3. **问题输入**：输入 @ 或点击“添加资料”打开同一个选择器。
4. **范围开关**：“搜索个人知识库”默认开，“允许联网”默认关。
5. **任务和答案**：实际采用的资料、真实进度、答案、引用和保存入口。

首次进入空草稿时尝试加入当前普通网页；缺少权限时只显示授权按钮。此后切页不自动替换或追加资料。用户可以主动添加新页面。当前页不可读，也不影响只问知识库。

## @ 选择器

分“已打开网页”和“个人笔记”两组，支持标题搜索。第一版只列当前浏览器窗口的 HTTP/HTTPS 标签页，不读取未选中网页的正文。网页本地筛选；笔记复用列表筛选 API，不为选择资料调用向量模型。

选择后生成卡片，输入框保留问题，附件数据单独记录 tabId 或 noteId，不靠解析 @标题 获取资料。支持上下键选择、Enter 确认、Escape 关闭、鼠标和独立添加按钮。没有结果时明确提示。

网页选中后检查权限、读取正文，显示需要授权/正在读取/已就绪/失败，不要求用户展开或确认正文。授权从明确点击发起，不在搜索列表时自动申请。笔记可预览，但提交时后端仍按 ID 读取最新版本。

最多 3 篇网页、3 条指定笔记。笔记按 ID 去重；网页按去掉片段的完整 URL 去重，保留 query 参数以区分不同内容。自动召回最多 3 条笔记，和指定笔记按 ID 去重。

## 范围的准确含义

| 用户选择 | 后端行为 |
| --- | --- |
| 只有网页，两个开关关闭 | 只使用提交的正文 |
| 没有网页，知识库开启 | 检索个人笔记，不要求当前页可读 |
| 指定笔记，知识库关闭 | 读取指定笔记，不搜索整个库 |
| 指定笔记，知识库开启 | 指定笔记加自动召回结果，去重 |
| 允许联网 | 模型可以按需搜索，不等于已经执行 |
| 没有附件、两个开关都关 | 提示先选择资料范围 |

开关表示“额外去哪里查”，不移除用户明确添加的资料。只问一条指定笔记时，保留笔记卡片，关闭两个开关即可，不增加另一套模式选择。

## API 目标契约

继续使用 POST /api/research/run。前后端一起把旧的单个 context 改成以下结构；这是目标接口，目前还不能据此请求。现有单篇接口仍为 question 加 context，context 已改为完整正文及读取时间，不再使用选区字段：

```json
{
  "question": "对比文章中的类型收窄和我的笔记",
  "materials": {
    "pages": [
      {
        "id": "page-local-1",
        "title": "TypeScript 文档",
        "url": "https://example.com/typescript",
        "text": "实际取得的正文……",
        "capturedAt": "2026-10-19T08:00:00.000Z",
        "completeness": "full"
      }
    ],
    "noteIds": ["12"]
  },
  "options": {
    "searchKnowledgeBase": true,
    "allowWebSearch": false
  }
}
```

研究请求的 completeness 只允许 full，不接受部分正文问答。full 表示已加载正文完整提取，不保证原站隐藏或未加载内容已取得。已取消三万字符拦截，采用 SDD-006 修订稿的完整正文直传；不再设计网页分段检索或分层总结。后端校验问题、数量、大小、网址和 ID，不把前端内容当成已核实事实。

JSON 阶段保留 answer、sources 等响应字段，增加 runId、实际采用的资料摘要和结构化提示。无网页时不要求 page。无来源网址的笔记仍可在插件内查看，不生成假网页链接。

tabId 留在扩展，不作为后端取网页的凭证。附件本地 ID、任务 runId、回答来源 ID 分开。用户添加的网页不会让模型获得任意 URL 的读取权限。

## 状态和恢复

分别保存三份数据：

- **当前浏览页**：跟随浏览器变化，维护可读性与权限。
- **研究草稿**：问题、网页快照、指定笔记、两个开关、保存编辑内容。
- **研究任务**：提交时固定的资料、状态、回答和来源。

由研究工作区统一持有草稿和任务状态。卡片、选择器、答案组件接收数据并发出操作，不各自存整份状态。先用 Vue composable 和会话存储，不提前引入全局框架。

按 windowId 保存草稿和最近一次完成结果；重开侧栏时读取中的附件需重试，运行中的任务标为中断，不自动重发。浏览器重启或扩展重载不承诺恢复。不做完整历史列表。

## 多来源笔记怎样保存

保存仍需编辑和确认。引用转换成普通具名 Markdown 链接，保留在笔记正文中，不强行假定只参考当前网页。

沿用 sourceTitle/sourceUrl 作为可选主要来源：默认取任务中第一篇网页，保存区允许选择其他实际来源或不设置；仅笔记问答可留空。不能拿此刻正在浏览的新网页当成原任务来源。其他来源通过正文链接保留，本轮不新增来源关系表。

## 当前可用的单篇／无网页接口

多资料 materials 接口留到 @ 阶段。目前 POST /api/research/run 接收：

```json
{
  "question": "我保存过哪些泛型笔记？",
  "context": null,
  "options": {
    "searchKnowledgeBase": true,
    "allowWebSearch": false
  }
}
```

使用网页时 context 仍是 SDD-001 的完整正文对象；关闭网页时发 null，不发送网页文字。options 省略时兼容旧请求，默认查知识库、关闭联网；显式提供时两个字段必须都是布尔值。无网页且两个开关都关闭会被拒绝。响应包含 runId 和实际采用的 options，已完成结果保留提交时的范围。

前端沿用 completedPageResearch:v2 会话键恢复最近结果与已记录的范围；旧结果未记录范围时保留答案，不倒推它曾经允许哪些工具。该能力不是完整草稿或聊天历史系统。
