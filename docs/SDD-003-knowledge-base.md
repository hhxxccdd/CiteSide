# SDD-003：保存笔记并用向量找回相关知识

> 2026-10-15 更新。对应 PRD 的 F7、F8。文中包含目标功能；保存与搜索接口已开始实现，侧栏编辑界面仍待完成。

## 这一部分做什么

用户提问并得到回答后，可以把有价值的内容整理成一条笔记。下次提问时，助手可以搜索这些笔记，把找到的内容用于回答。第一版只服务本地单人，不做账号和云同步。

这不是“AI 每说一句就自动记住”。**只有用户点击保存并确认，知识库才会增加一条。**

## 怎样保存

1. 一次回答完成后，显示“保存到知识库”。失败、停止或还在生成的任务不显示保存入口。
2. 点击后在侧栏打开编辑区，预填一个标题和本次回答。标题与正文都是可编辑的输入框；用户可以修改、取消，也可以不保存。
3. 编辑区同时显示原网页的标题、网址以及本次问题，方便用户判断来源；保存时保留这些信息。保存前可以展开本次回答的来源卡片核对内容。
4. 点击“确认保存”后，NestJS 用笔记的标题和正文请求文本向量模型，得到一组数字，再把笔记和向量一起写入 PostgreSQL。全部成功才显示“已保存”；向量生成或写库失败时保留编辑内容并提示重试，不能留下只有正文、却无法被检索到的半成品。

保存的是用户确认过的**笔记内容**，不把它标成已验证事实。第一次不做自动摘要、自动拆分多条知识或批量导入。

点击“确认保存”是用户主动发起的一次普通后端请求，不算 Qwen 自主决定执行的 Agent 工具。保存过程中禁用重复提交；失败时保留用户刚编辑的标题和正文。保存成功后显示笔记 ID 和“查看笔记”入口。

## 怎样查看和修改

侧栏有“我的知识”入口，打开后可按最近保存顺序看列表。每条能打开详情、修改标题与正文、删除。删除前让用户确认；删除成功后，后续搜索不再返回这条笔记。

知识库页面提供一个简单筛选框，按标题或正文查找，方便用户自己浏览。这个界面筛选不等于提问时的向量检索。没有结果时显示“没有找到相关笔记”，列表只显示有限数量。

## 下次提问怎样用到旧笔记

NestJS 提供 search_knowledge_base 工具。每次提问都执行搜索；后端用问题和本次选区组成检索内容，交给**同一个文本向量模型**生成向量；再用 pgvector 按余弦距离对已保存笔记排序，最多取 5 条候选。Qwen 进一步判断候选能否直接帮助回答，最多留下 3 条；无关时返回空列表。返回条目 ID、标题、正文、原网页来源和相似度。工具执行的开始、完成、失败都进入本次任务的真实进度。

回答可以同时使用当前选区和查到的旧笔记。界面分别标明“当前网页”和“知识库笔记”，并展示真正返回的标题、来源。点击笔记卡片可查看保存的正文，并打开笔记原网页。相似只代表“可能相关”，不等于事实正确；回答应忽略无关候选，不能把所有返回的笔记都说成已采用的证据。没有笔记或没有可信结果时，如实告诉模型“没有找到”。

第一版每条短笔记只生成**一个向量**，不切成很多段。pgvector 默认的精确相似度搜索已足够验证小型个人知识库，先不建 HNSW 或 IVFFlat 索引。用几组相关、换说法、无关的问题检查结果；相似度过滤值根据这些样例确定，不把未经测试的分数写死为“相关”。

生成向量需要单独的文本向量模型，它不是负责写回答的 Qwen 聊天模型。第一版拟用阿里云 Model Studio 的 text-embedding-v4，固定使用 1024 维；保存笔记和搜索问题必须使用相同模型与维度。开始实现前先确认当前账号所在地域可调用该模型。模型名和密钥只在后端配置。

## 数据放在哪里

PostgreSQL 安装 pgvector 后，为每条笔记保存：独立 ID、标题、正文、1024 维向量、向量模型名、原问题、原网页标题和网址、创建与修改时间。原网页选区不自动存成另一份全文；用户想保留其中一句，可以自己写进笔记正文。修改标题或正文时重新生成向量，成功后再一起更新；删除笔记时这些字段一起删除。

普通提问只产生任务和事件记录，不自动产生笔记。未确认的选区预览仍只在扩展会话中。

如果以后更换向量模型或维度，需要重新为旧笔记生成向量；不能直接混用两种模型的数字。

## 文件准备怎样放

    apps/extension/src/
      features/knowledge-base/       保存编辑区、列表、详情和搜索界面
      features/research-run/         回答页的“保存到知识库”入口

    apps/api/src/
      knowledge/                     笔记的保存、列表、修改、删除和向量查找
        embedding/                   调用文本向量模型；保存和搜索共用
      database/                      pgvector 扩展与知识表的数据库变更
      research/tools/                search_knowledge_base 与读取当前选区的工具

界面、数据库操作、工具调用各有位置。先按这两个功能目录组织，不提前做通用记忆框架。

## 做完后怎么检查

1. 不点击保存时，知识库没有新增内容。
2. 修改预填标题和正文并保存，重新打开侧栏仍能找到它；保存失败时编辑内容不丢失。
3. 能搜索、修改和删除；删除后的条目不再出现在列表或工具结果里。
4. 用不同措辞提相关问题时，工具确实通过向量检索返回已保存的条目；回答来源能找到对应 ID 和原网页网址。
5. 修改笔记后，下一次检索用新内容；向量模型失败时保存或修改不留下半成品。
6. 无关问题或搜不到时，不展示虚构的笔记或来源。
